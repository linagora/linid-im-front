# 🌐 **i18n Management System**

The LinID project provides a **centralized i18n system** to manage translations and application languages dynamically.

---

## **📚 Overview**

The i18n system works as follows:

1. Loads a global configuration from `public/i18n.json`
2. Loads translation files for the active locale
3. Provides an API to access translations in components
4. Allows dynamic language switching at runtime

This approach simplifies multilingual support and allows easy addition of new languages.

---

## **🔄 How It Works**

### **1. Global Configuration**

The main configuration is in `public/i18n.json`:

```json
{
  "languages": ["fr-FR", "en-US"],
  "locale": "fr-FR"
}
```

- `languages`: list of available languages
- `locale`: default active language

---

### **2. Translation Files**

Each language has its own JSON file in `public/i18n/`:

```json
// public/i18n/en-US.json
{
  "application": {
    "title": "LinID - Identity Manager",
    "version": "Development version"
  },
  "Homepage": {
    "title": "LinID Identity Manager",
    "intro": "<strong>LinID Identity Manager</strong> is an open source...",
    "opensource": "<strong>Open source project</strong>...",
    "license": "This project is released under...",
    "links": "<ul>...</ul>",
    "branding": "<div>...</div>"
  }
}
```

```json
// public/i18n/fr-FR.json
{
  "application": {
    "title": "LinID - Gestionnaire d'identités",
    "version": "Version de développement"
  },
  "Homepage": {
    "title": "LinID Identity Manager",
    "intro": "<strong>LinID Identity Manager</strong> est une solution...",
    "opensource": "<strong>Projet open source</strong>...",
    "license": "Ce projet est distribué sous...",
    "links": "<ul>...</ul>",
    "branding": "<div>...</div>"
  }
}
```

- Files follow a **key/value structure**
- Nested objects are allowed to organize translations
- Use `{placeholder}` syntax for dynamic values (e.g., `"minLength": "Must be at least {min} characters"`)

---

### **3. Key Structure Convention**

Translations are organized by namespace:

| Namespace     | Description                                        |
| ------------- | -------------------------------------------------- |
| `application` | Application metadata (title, version)              |
| `Homepage`    | Homepage content (title, intro, license, branding) |

Additional namespaces are added by remote modules (e.g., `moduleUsers` for user management translations).

---

### **4. Default Translation Values**

The `src/i18n` folder contains default translation values used as fallback when JSON files are not yet loaded:

```typescript
// src/i18n/en-US/index.ts
export default {
  application: {
    title: 'LinID - Identity Manager',
    version: 'Development version',
  },
  Homepage: {
    title: 'LinID Identity Manager',
  },
};
```

These default values ensure the application has translations available during initialization and enable IDE autocompletion for translation keys.

---

### **5. Using Translations in Components**

```vue
<template>
  <q-page>
    <h1>{{ $t('Homepage.title') }}</h1>
    <p>{{ $t('application.version') }}</p>
  </q-page>
</template>

<script setup lang="ts">
import { useI18n } from 'vue-i18n';

const { t } = useI18n();

// Access translations programmatically
const title = t('Homepage.title');
</script>
```

---

### **6. Scoped Translations with `useScopedI18n`**

For modules and reusable components, use the `useScopedI18n` composable from corelib. It automatically prefixes all translation keys with a namespace, making components reusable across different contexts.

```vue
<script setup lang="ts">
import { useScopedI18n } from '@linagora/linid-im-front-corelib';

// All keys are prefixed with 'moduleUsers.homepage'
const { t, te, translateOrDefault } = useScopedI18n('moduleUsers.homepage');

// t('title') → translates 'moduleUsers.homepage.title'
// te('title') → checks if 'moduleUsers.homepage.title' exists
// translateOrDefault('Default', 'title') → returns translation or 'Default'
</script>

<template>
  <h1>{{ t('title') }}</h1>
</template>
```

**Available functions:**

| Function             | Description                                             |
| -------------------- | ------------------------------------------------------- |
| `t(key, ...args)`    | Translate a key (supports interpolation, pluralization) |
| `te(key)`            | Check if a translation key exists                       |
| `tm(key)`            | Get raw message without formatting                      |
| `translateOrDefault` | Return translation or fallback to default value         |

> For detailed documentation, see the [corelib i18n documentation](../linid-im-front-corelib/docs/i18n.md).

---

### **7. Adding a New Language**

1. Add the new language in `public/i18n.json`:

```json
{
  "languages": ["fr-FR", "en-US", "es-ES"],
  "locale": "fr-FR"
}
```

2. Create a translation file `public/i18n/es-ES.json` with the same structure as existing files.

3. Refresh the application; the new language will be loaded automatically.

---

## **⚠️ Important Notes**

- **No automatic file fallback**: If a key is missing in the active language, `fallbackLocale` will be used
- **Consistent key structure**: Ensure all translation files follow the same object hierarchy
- **Asynchronous loading**: JSON files are loaded dynamically to keep the bundle lightweight
- **Default values**: The `src/i18n/en-US/index.ts` file provides fallback translations used during app initialization before JSON files are loaded
- **API translations**: The system also merges translations from the API (`/i18n/{lang}.json`) with app translations

# 🌐 **i18n Management System**

The LinID project provides a **centralized i18n system** to manage translations and application languages dynamically.

---

## **📚 Overview**

The i18n system works as follows:

1. Loads a global configuration from `public/i18n.json`
2. Loads translation files for the active locale
3. Provides an API to access translations in components
4. Allows dynamic language switching at runtime

This approach simplifies multilingual support and allows easy addition of new languages.

---

## **🔄 How It Works**

### **1. Global Configuration**

The main configuration is in `public/i18n.json`:

```json
{
  "languages": ["fr-FR", "en-US"],
  "locale": "fr-FR"
}
```

- `languages`: list of available languages
- `locale`: default active language

---

### **2. Translation Files**

Each language has its own JSON file:

```json
// public/i18n/en-US.json
{
  "application": {
    "title": "Linid - Identity Manager",
    "version": "Dev version"
  }
}
```

```json
// public/i18n/fr-FR.json
{
  "application": {
    "title": "Linid - Gestionnaire d'identité",
    "version": "Version Dev"
  }
}
```

- Files follow a **key/value structure**
- Nested objects are allowed to organize translations

---

### **3. Initialization**

The i18n system is initialized using the global configuration:

```typescript
import {
  fromDot,
  merge,
  setI18nInstance,
} from '@linagora/linid-im-front-corelib';
import { api } from 'boot/axios';
import type messages from 'src/i18n';
import { createI18n, type I18n } from 'vue-i18n';
import { defineBoot } from '#q-app/wrappers';

(...)

export default defineBoot(async ({ app }) => {
  const i18nConfig: {
    /**
     * Array of supported language codes.
     */
    languages: string[];
    /**
     * Default locale of the application.
     */
    locale: string;
  } = await fetch('/i18n.json').then((res) => res.json());

  const messages: Record<string, unknown> = {};

  for (const lang of i18nConfig.languages) {
    const appMessages = await fetch(`/i18n/${lang}.json`)
      .then((res) => res.json())
      .catch(() => ({}));
    const apiMessages = await api
      .get(`/i18n/${lang}.json`)
      .then(({ data }) => fromDot(data))
      .catch(() => ({}));

    messages[lang] = merge(apiMessages, appMessages);
  }

  const i18n = createI18n<{ message: MessageSchema }, MessageLanguages>({
    locale: i18nConfig.locale,
    legacy: false,
    fallbackLocale: i18nConfig.languages[0],
    messages,
  }) as I18n;

  setI18nInstance(i18n);

  app.use(i18n);
});
```

- `messages` contains all loaded translations
- `locale` sets the active language
- `fallbackLocale` is used if a key is missing in the active locale

---

### **4. Adding a New Language**

1. Add the new language in `public/i18n.json`:

```json
{
  "languages": ["fr-FR", "en-US", "es-ES"],
  "locale": "fr-FR"
}
```

2. Create a translation file `public/i18n/es-ES.json`:

```json
{
  "application": {
    "title": "Linid - Identity Manager",
    "version": "Dev version"
  }
}
```

3. Refresh the application; the new language will be loaded automatically.

---

## **⚠️ Important Notes**

- **No automatic file fallback**: If a key is missing in the active language, `fallbackLocale` will be used
- **Consistent key structure**: Ensure all translation files follow the same object hierarchy
- **Asynchronous loading**: JSON files are loaded dynamically to keep the bundle lightweight
